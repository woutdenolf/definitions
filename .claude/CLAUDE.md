# Branch `nxds` — context for Claude

This branch is a **prototype and proposal**, not yet accepted by the NIAC. It
adds NXDS (NeXus Definition Schema): a schema language whose meaning is written
down, so that validators, readers, writers and the documentation stop
re-implementing the prose rules of the manual.

Start by reading, in this order:

1. `wip/proposal.md` — the proposal to the NIAC (phases 0–4, the motion, risks
   R1–R15, questions Q1–Q14).
2. `nxds/spec/nxds.md` — the draft specification. **It is the source of
   truth**: when code, generated files or the proposal disagree with it, the
   spec wins (or is changed first).
3. `wip/design-decisions.md`, `wip/research-notes.md`, `wip/performance.md` —
   background.

## Layout

| Path | What | Edited by |
|---|---|---|
| `base_classes/`, `applications/`, `contributed_definitions/` | classes: `*.nxdl.xml` (today) or `*.nxds.yaml` (phase 2; `NXslit`, `NXmonopd` are converted as a demonstration only) | people |
| `nxds/spec/nxds.md` | the specification | people |
| `nxds/metaschema/*.json` | JSON Schemas of class files, resolved files, index, findings, catalogue — **written by hand**; the code follows them | people |
| `nxds/conformance/` | resolution and validation cases with expected output; validation cases share `validation/bundle/` | people (expected files via `run.py --update`, then reviewed) |
| `nxds/generated/` | `index.json`, `resolved/*.json`, `source/` (NXDL translated), `translation.md`, `report.txt` | `make nxds` only — never by hand |
| `nxds_tools/` | independent Python project: compiler (NXDL→NXDS), resolver, validator, docs, legacy NXDL | people |
| `wip/` | proposal, slides (`wip/slides/index.html`, reveal.js, Markdown inside), examples per phase (`wip/examples/`, regenerated by `regenerate.sh`) | people / script |
| `dev_tools/` | the existing NXDL tooling; reads `build/nxdl` (`make nxds-legacy`) so NXDS classes still appear in the manual | people |

## Commands

```bash
make install                      # installs nxds_tools (editable) and the rest
make nxds                         # regenerate nxds/generated (CI checks it is up to date)
python -m pytest nxds_tools/tests
python nxds/conformance/run.py    # all conformance cases
make nxds-legacy nxtest           # NXDL tree incl. generated NXDL for NXDS classes
python -m nxds_tools validate FILE.h5 --bundle nxds/generated [--expect NXxxx] [--partial] [--json]
PYTHON=python wip/examples/regenerate.sh
```

Without installing: `PYTHONPATH=nxds_tools/src`.

## Machine rules (important)

The author's workstation has 7.7 GB of RAM shared with an IDE and a browser;
running several Python jobs at once crashed it before.

- Run every Python, pytest or make command under a hard memory limit, one at a
  time, for example
  `systemd-run --user --scope -p MemoryMax=900M -p MemorySwapMax=0 nice -n 19 ionice -c3 <cmd>`,
  and only when at least ~1 GB more is free (`free -m`).
- Never run several heavy agents or jobs in parallel; no `pytest -n`, no
  multiprocessing. Split the test suite in halves if needed.
- Keep test HDF5 files tiny.
- Never install packages; ask the user.

## Rules for changes

- Change the spec first, then the metaschema, then the code, then the
  conformance cases (expected files are the reference, not the output of
  `nxds_tools`).
- Every NIAC-dependent value is marked `provisional: [Qn]`; the questions are
  listed in the proposal §12 and in `index.json` `decisions`.
- Translation rules T0–T19 live as data in `nxds_tools/src/nxds_tools/translation.py`.
- After changing anything that affects output: `make nxds`, regenerate the
  examples, run tests and conformance.
- Prose for the NIAC (proposal, slides) uses simple English: short sentences,
  no jargon without a glossary entry; many readers are not native speakers.
- After writing prose for others, have a sub-agent without your context read it
  and report what is unclear.
- Do not commit unless asked; push only to the remote `wout`, never `origin`.
